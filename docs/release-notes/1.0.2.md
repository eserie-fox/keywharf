# keywharf 1.0.2

`1.0.2` is a release-closure patch focused on aligning version metadata, command terminology, documentation, and tests with the current workspace and host-repo model. It does not introduce new CLI commands or a new architecture.

## Highlights

- Aligned runtime/package version metadata on the existing single source (`keywharf.version.__version__`).
- Finalized command terminology around `repo init`, `repo sync`, and `repo host ...` in release-facing docs.
- Kept host management layering explicit: host shell, endpoint options, and authentication options with optional comments.
- Revalidated release readiness through targeted checks, full tests, and build artifact smoke checks.

## Notable Changes

- Bumped the version to `1.0.2` and kept dynamic package version loading from `pyproject.toml`.
- Finalized the `1.0.2` entry in `CHANGELOG.md` as the canonical change ledger.
- Started publishing per-version release notes under `docs/release-notes/` from this release onward.
- Updated CLI help-group tests to assert help content rather than environment-sensitive group-help exit codes.
- Verified release artifacts with `python -m build` and `twine check dist/*`.

## Upgrade Note

No config migration is required for existing workspaces or host-repo data.

This release is focused on release-quality closure and documentation/test consistency.
